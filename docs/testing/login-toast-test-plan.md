# 로그인 에러 토스트 누적 버그 - Playwright E2E 테스트 계획서

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 |
| 작성일 | 2026-08-05 |
| 작성자 | leeyonghyok |
| 대상 시스템 | 진격의 박병장 (military_life, Django 6.0.7) |
| 관련 버그 | 로그인 실패 에러 토스트가 홈 화면 이동 시 누적되어 표시되고 사라지지 않는 문제 |
| 관련 수정 커밋 | `military_life/account/views.py` (중복 `messages.error()` 제거), `military_life/static/js/common.js` (`initToast()` 추가) |

## 1. 목적

로그인 실패 시 발생하던 에러 토스트 누적/미소멸 버그가 실제로 해결되었는지, 그리고 관련 정상 플로우(로그인 성공/실패, 토스트 표시·닫기)가 회귀 없이 동작하는지를 Playwright 기반 E2E 테스트로 검증한다.

## 2. 버그 배경

- `account/views.py`의 `login_view`는 로그인 폼 검증 실패 시 `messages.error()`를 호출해 세션 메시지 큐에 에러 메시지를 쌓았다.
- 로그인 화면이 상속하는 `templates/base_auth.html`에는 `{% if messages %}` 렌더링 블록이 없어, 쌓인 메시지가 로그인 화면에서 전혀 소비(consume)되지 않았다. (화면에는 별도로 `form.non_field_errors`가 표시되어 "정상적으로 사라지는 것처럼" 보였음)
- 로그인을 여러 번 실패한 뒤 홈 화면(`templates/base.html`, `{% if messages %}` 토스트 렌더링 블록 있음)으로 이동하면, 그동안 쌓여있던 메시지가 한 번에 모두 렌더링되어 동일한 에러 토스트가 중복으로 표시되었다.
- 추가로 `static/js/common.js`에 토스트 닫기 버튼/자동 소멸 로직이 전혀 구현되어 있지 않아, 한 번 뜬 토스트는 페이지를 벗어나기 전까지 화면에 계속 남아 있었다.
- **수정 내용**: (1) `login_view`의 중복 `messages.error()` 호출 제거, (2) `common.js`에 `initToast()` 추가하여 닫기 버튼 클릭 시 및 4초 후 자동으로 토스트가 사라지도록 처리.

## 3. 테스트 범위

**포함**
- 로그인 실패 시 에러 메시지 표시 및 미누적 확인
- 로그인 실패 반복 후 로그인 성공 시 홈 화면의 토스트 잔존 여부 확인 (핵심 회귀 케이스)
- 정상 로그인 성공 플로우
- 홈 화면 토스트 닫기 버튼 동작
- 홈 화면 토스트 자동 소멸(4초) 동작

**제외**
- 회원가입, 회원정보 수정/탈퇴, 게시판, 챗봇 등 로그인/토스트와 무관한 기능
- 성능/부하 테스트, 접근성(a11y) 테스트, 크로스브라우저(파이어폭스/사파리) 테스트 (1차는 Chromium 단일 브라우저)
- 수정 전 코드로 되돌려 버그 재현 여부를 별도 검증하는 단계 (요청에 따라 제외, 현재 수정된 코드 기준 PASS 여부만 확인)

## 4. 테스트 환경

| 구분 | 내용 |
|---|---|
| 프레임워크 | Playwright (Python), pytest, pytest-django, pytest-playwright |
| 대상 서버 | pytest-django `live_server` fixture로 기동되는 Django 개발 서버 (테스트 전용 임시 sqlite DB, 기존 `db.sqlite3` 데이터에는 영향 없음) |
| 브라우저 | Chromium (headless) |
| 테스트 계정 | 테스트마다 `django_user_model.objects.create_user()`로 생성하는 고정 계정 (실 계정 불필요) |
| 실행 위치 | 로컬 `.venv` (Windows) |
| 의존 패키지 | `requirements-test.txt` (`pytest`, `pytest-django`, `pytest-playwright`) + `playwright install chromium` |

## 5. 테스트 케이스

| ID | 시나리오 | 사전조건 | 절차 | 기대 결과 |
|---|---|---|---|---|
| TC-01 | 로그인 1회 실패 시 에러 표시 | 유효한 테스트 계정 존재 | 로그인 화면에서 올바른 아이디 + 틀린 비밀번호로 제출 | 로그인 페이지에 `.alert-danger`로 "아이디 또는 비밀번호가 올바르지 않습니다" 표시, 페이지 유지(리다이렉트 없음) |
| TC-02 (핵심 회귀 케이스) | 반복 실패 후 로그인 성공 시 홈 화면 토스트 미누적 | 유효한 테스트 계정 존재 | 틀린 비밀번호로 3회 연속 로그인 시도 → 마지막에 올바른 비밀번호로 로그인 | 홈(`/`)으로 정상 이동하며, 홈 화면의 `.app-toast--error` 요소 개수가 0개 (수정 전에는 3개가 누적되어 표시됨) |
| TC-03 | 정상 로그인 성공 | 유효한 테스트 계정 존재 | 처음부터 올바른 아이디/비밀번호로 로그인 | 홈으로 리다이렉트, 에러 토스트 없음 |
| TC-04 | 토스트 닫기 버튼 동작 | 홈 화면에 `messages` 토스트가 떠 있는 상태 | 토스트의 닫기(X) 버튼(`[data-toast-close]`) 클릭 | 클릭한 토스트가 `app-toast--hide` 애니메이션 후 DOM에서 제거됨 |
| TC-05 | 토스트 자동 소멸 | 홈 화면에 `messages` 토스트가 떠 있는 상태 | 아무 조작 없이 약 4초 대기 | 토스트가 자동으로 사라짐 |

TC-04/05의 토스트는 로그인 실패가 아닌 기존 `messages` 흐름(예: 회원정보 수정 성공 메시지, `account/views.py`의 `messages.success()`)을 그대로 이용해 발생시킨다.

## 6. 완료 기준 (Exit Criteria)

- TC-01~05 전체 PASS
- 특히 TC-02(핵심 회귀 케이스)가 PASS하여, 로그인 반복 실패 후 홈 화면에 에러 토스트가 누적되지 않음을 확인
- 테스트 실행 후 실 데이터베이스(`military_life/db.sqlite3`)에 변경이 없음을 확인

## 7. 일정

| 단계 | 내용 |
|---|---|
| 1차 | 테스트 환경 구축 (패키지 설치, `pytest.ini` 구성) |
| 2차 | E2E 테스트 코드 작성 (TC-01~05) |
| 3차 | 테스트 실행 및 결과 수집 |
| 4차 | 결과보고서 작성 |

※ 본 문서(계획서) 작성 이후 위 1~4차는 별도 요청 시 진행 예정.

## 8. 리스크 및 제약사항

- `playwright install chromium` 실행 시 브라우저 바이너리 다운로드를 위한 네트워크 접근이 필요하다.
- 프로젝트 루트 `.env`가 `military_life/.env` 위치에 없어 `OPENAI_API_KEY`, `NEO4J_*` 등이 `None`으로 로드되지만, 로그인/홈/토스트 플로우는 해당 값에 의존하지 않으므로 테스트에 영향 없음.
- 본 테스트는 로그인·토스트 버그 수정 검증에 한정되며, 전체 애플리케이션 회귀 테스트를 대체하지 않는다.
