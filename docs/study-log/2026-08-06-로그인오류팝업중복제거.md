# 로그인 실패 시 중복 오류 팝업 제거

## 지시 내용
로그인 화면에서 비밀번호를 잘못 입력하면, 로그인 화면 자체에는 오류 메시지가 이미 표시되는데
그와 별개로 홈 화면으로 넘어갔을 때 오류 토스트 팝업이 떴다가 사라지는 중복 현상이 있었다.
이 팝업이 아예 뜨지 않도록 수정.

## 원인 분석
- `account/views.py`의 `login_view`는 로그인 폼이 유효하지 않을 때
  `messages.error(request, "아이디 또는 비밀번호가 올바르지 않습니다.")`를 호출하고
  `account/login.html`을 그대로 렌더링했다.
- `account/login.html`은 `base_auth.html`을 상속하는데, `base_auth.html`에는
  `messages` 프레임워크를 렌더링하는 `{% if messages %}` 토스트 블록이 없다.
  (토스트 블록은 `base.html`에만 존재하며, 홈/챗봇 등 다른 페이지가 그것을 상속한다.)
- 따라서 `messages.error`로 추가된 메시지는 로그인 화면에서는 표시되지 않고
  세션(메시지 스토리지)에 남아 있다가, 사용자가 이후 `base.html`을 사용하는
  다른 페이지(홈 화면 등)로 이동했을 때 뒤늦게 토스트로 나타났다.
- 한편 로그인 화면 자체에는 Django `AuthenticationForm`의 기본 오류 메시지
  ("올바른 사용자 이름와/과 비밀번호를 입력하십시오...")가 `form.non_field_errors`를 통해
  `login.html` 안에서 이미 인라인으로 표시되고 있었다. 즉 같은 오류가
  (1) 로그인 화면의 인라인 메시지 + (2) 엉뚱한 화면에서 뜨는 토스트, 이렇게 중복으로 노출되고 있었다.

## 수정 전
```python
# account/views.py
def login_view(request):
    if request.method == "POST":
        form = LoginForm(request, data=request.POST)
        if form.is_valid():
            user = form.get_user()
            login(request, user)
            next_url = request.POST.get('next') or reverse('home:home')
            return redirect(next_url)
        else:
            messages.error(request, "아이디 또는 비밀번호가 올바르지 않습니다.")
    else:
        form = LoginForm(request)
    return render(request, 'account/login.html', {'form': form})
```

## 수정 후
```python
# account/views.py
def login_view(request):
    if request.method == "POST":

            user = form.get_user()

```

## 변경 이유 및 개념 설명
- Django의 `messages` 프레임워크는 "다음 요청(들)에서 한 번 보여줄 메시지"를 세션/쿠키에
  저장해두는 방식이라, 저장 시점의 페이지에서 바로 소비(렌더링)하지 않으면
  다른 페이지로 넘어갈 때 뒤늦게 나타날 수 있다. 이번 버그는 로그인 페이지의 템플릿
  (`base_auth.html`)이 messages를 렌더링하지 않아서 발생한, 전형적인 "메시지 소비 누락" 사례다.
- 로그인 실패라는 동일한 상황에 대해 이미 폼의 `non_field_errors`가 로그인 화면에
  인라인으로 표시되고 있었으므로, `messages.error` 호출은 불필요한 중복이었다.
  중복 알림 채널을 없애기 위해 `messages.error` 호출만 제거하고, 폼 자체의 오류 표시는 그대로 두었다.
- 참고: `messages.success`(회원정보 수정), `messages.info`(탈퇴 완료) 등 다른 `messages` 호출은
  전부 `base.html`을 쓰는 페이지(홈 등)로 리다이렉트된 이후에 뜨는 것이라 정상 동작하며,
  이번 수정 대상이 아니다.
