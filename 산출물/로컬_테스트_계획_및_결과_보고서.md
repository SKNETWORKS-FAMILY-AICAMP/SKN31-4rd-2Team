## 1. 목적

account, home, chatbot, records, board 5개 화면의 기능이 요구사항대로 실제로 동작하는지 Playwright로 확인한다.

## 2. 테스트 범위

**포함**
- 회원가입/로그인/정보수정/탈퇴, 홈 화면, 챗봇 질의응답, 개인기록(일지/디데이/목표), 게시판(글/댓글/좋아요/신고/검색/정렬) 전체 기능
- 챗봇 응답 속도
- 비밀번호가 안전하게 저장되는지, 다른 사람의 개인 데이터에 접근할 수 없는지 (보안 관련 항목)
- 챗봇은 실제 OpenAI, Qdrant, Neo4j를 그대로 연동해서 테스트한다 (가짜 응답을 쓰지 않음)

**제외**
- 부하/성능 테스트, 장애인 접근성 테스트
- 여러 브라우저 테스트 — Chromium 하나만 사용
- 어려운 법률 용어를 쉽게 풀어주는지, 지식베이스를 쉽게 업데이트할 수 있는지 — 화면 클릭만으로 확인하기 어려워 별도 체크리스트/코드 리뷰로 확인
- 서버 방화벽 등 인프라 보안 설정 — 화면 테스트 대상이 아님
- 북마크 기능 — 이번 버전에는 없음(다음 버전에서 개발 예정)
- 관리자 화면 테스트

## 4. 공통 유의사항

- 로그인이 필요한 화면(게시판, 개인기록, 챗봇 등)은 테스트 시작 전에 미리 로그인된 상태로 만들어둔다.
- 챗봇 답변은 조금씩 이어서 오는 방식(스트리밍)이라, 다 올 때까지 기다렸다가 확인한다.
- 챗봇 답변의 정확한 "내용"은 매번 달라질 수 있으므로 (a) 로딩이 끝나는지 (b) 답변이 비어있지 않은지 (c) 에러 없이 끝까지 오는지만 확인한다.
- 게시판의 글쓰기/수정/삭제/좋아요/신고는 화면이 바로 갱신되는 방식이라, 버튼을 누른 뒤 서버 응답까지 확인한다.

## 3. 진행 중 발견한 환경 문제 (테스트 대상 화면의 버그가 아님)

| 문제 | 증상 | 원인 | 해결 |

## 4. 앱별 실행 결과

### 4-1. 회원가입/로그인/내 정보 — 8개 중 8개 구현

계획서의 케이스를 모두 작성해 전부 통과시켰다. (TC-ACCT-02 간부 회원가입은 병사 가입과 화면·로직이 거의 같아 이번엔 생략)

### 4-2. 홈 화면 — 3개 중 3개 구현 (전체 완료)

### 4-3. 개인기록 — 6개 구현

TC-REC-02(일지 수정), TC-REC-05(캘린더 월 이동)는 시간 관계상 이번엔 만들지 않았다. 목표 추가 취소 버튼은 실제 화면의 버튼(닫기 버튼)을 확인해서 정확한 걸로 작성했다.

### 4-4. 게시판 — 12개 전체 구현 (전체 완료)

- **게시글 신고**: 화면에는 아직 신고 버튼/입력창이 없다(뒤에서 처리하는 로직은 있음). 그래서 이 테스트는 화면 클릭이 아니라 서버에 직접 요청을 보내서 신고가 접수되는지만 확인했다. **화면에 신고 버튼이 빠져 있는 건 실제로 고쳐야 할 부분**이라 담당자에게 따로 알릴 필요가 있다.
- **로그인 없이 게시판 접근**: 게시판 목록 화면은 로그인 없이 들어가도 로그인 화면으로 넘어가지 않고, 개발 편의를 위해 첫 번째 계정으로 자동 로그인되는 기능이 있다. 원래 "로그인 화면으로 이동"을 기대했던 시나리오였는데, 실제로는 그렇게 동작하지 않아서 "이 동작 자체가 맞는지" 확인하는 내용으로 바꿔 작성했다.

### 4-5. 챗봇 — 3개 구현 (실제 API 비용 발생)

실제 OpenAI/Qdrant/Neo4j를 그대로 부르기 때문에 질문 하나마다 실제 비용이 든다. 그래서 이번엔 아래 3개만 확인했다.

- 로그인 없이 챗봇 접근 → 로그인 화면으로 이동 (비용 없음)
- **질문 1건**을 보내서 답변이 실시간으로 오는지, 답변이 끝까지 잘 오는지 확인하면서, 같은 답변 안에서 **출처가 화면에 표시되는지도 함께 확인**했다 → 실제로 질문을 보내본 결과, 답변 내용 어디에도 출처/근거 문서가 표시되지 않는 것을 확인했다(내부적으로는 출처 데이터를 가지고 있지만 화면에 연결이 안 되어 있음).
- 질문 1건을 추가로 보내 대화가 사이드바 목록에 잘 저장되는지 확인

대화 다시 보기/삭제/새 대화 시작/FAQ 클릭/통신 오류 처리는 비용과 시간 문제로 이번엔 만들지 않았다.

> 참고: 이번 확인으로 실제 OpenAI 질문 2건이 발생했다. 정확한 비용은 OpenAI 사용량 페이지에서 별도로 확인이 필요하다.

### 4-6. 품질(비기능) 테스트 — 이번엔 만들지 않음

시간 관계상 손대지 못했다. 비밀번호 안전 저장, 개인정보 접근 제한 확인은 서비스 보안의 핵심이라 다음에 가장 먼저 만들 것을 권장한다.

## 5. 테스트를 만들면서 알게 된 화면의 실제 동작

계획서는 코드를 읽고 작성했지만, 실제로 클릭해보니 아래처럼 예상과 다르게 동작하는 부분들이 있었다. 화면이 잘못됐다는 뜻이 아니라, "사람이 보는 화면 그대로" 클릭해야 한다는 흔한 패턴들이다.

- 회원가입/정보수정 화면의 "병사/간부", "계급" 선택 버튼은 겉보기엔 버튼처럼 보이지만 실제로는 숨겨진 선택 항목이라, **버튼처럼 보이는 부분(라벨)을 클릭**해야 동작한다.
- 게시판 글쓰기의 카테고리 선택도 마찬가지로, 겉으로 보이는 버튼 모양을 클릭해야 한다.
- 게시글 수정/삭제 메뉴는 점 3개(⋮) 같은 버튼을 먼저 눌러 메뉴를 펼쳐야 그 안의 항목이 눌린다.
- 일지/목표/게시글 삭제 버튼은 누르면 "정말 삭제하시겠습니까?" 확인창이 뜨는데, 이 확인창을 자동으로 승인하도록 처리해주지 않으면 삭제가 조용히 무시된다(에러도 안 떠서 처음엔 원인을 찾기 어려웠다).
